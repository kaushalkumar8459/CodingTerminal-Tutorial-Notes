# Day 43 Interview Questions — Custom Attribute Directives

## Interview Goal
Explain **Custom Attribute Directives**, implement the relevant Angular pattern, discuss trade-offs, and apply it to a realistic JobHub scenario.

## Interview Questions

### 1. How can a custom directive accept configuration from its host template?
**Expected Answer:** By declaring an `input()` (or `@Input`) property that the host template binds a value to, such as `[color]="highlightColor"`.

### 2. What API lets a directive expose an input in modern Angular?
**Expected Answer:** The signal-based `input()` function, which can also define a default value.

### 3. What makes a directive reusable across different features?
**Expected Answer:** A small, predictable contract with configurable inputs and no dependency on a single page or feature.

### 4. Where should business state live instead of inside a directive?
**Expected Answer:** In a service or the owning component/feature, not hidden inside a presentation directive.

### 5. What is the difference between a directive and a reusable component when both add visual behavior?
**Expected Answer:** A component owns its own markup and structure; a directive only enhances an existing host element and has no template of its own.

### 6. Why should a directive avoid becoming a hidden service or global state manager?
**Expected Answer:** It breaks the directive's single responsibility, makes behavior hard to predict, and couples presentation to application state.

### 7. What is a common mistake when building a directive with multiple responsibilities?
**Expected Answer:** Overloading one directive with many unrelated behaviors instead of keeping its contract small and focused.

### 8. JobHub scenario: build an appStatus directive supporting Active, Pending, Finished, and Cancelled states. How would you keep this directive focused and safe?
**Expected Answer:** Accept a status input, map it to a host class inside the directive, and avoid mutating application data or performing side effects.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not memorize syntax alone. Explain why the pattern fits the problem and which layer owns the responsibility.
