# Day 48 Interview Questions — Directive and Pipe Design Patterns

## Interview Goal
Explain **Directive and Pipe Design Patterns**, implement the relevant Angular pattern, discuss trade-offs, and apply it to a realistic JobHub scenario.

## Interview Questions

### 1. How do you decide between a component, a directive, and a pipe for a given requirement?
**Expected Answer:** Use a component when you own UI structure, a directive when you enhance an existing host element with reusable behavior, and a pipe when you transform a value for display.

### 2. What are the traits of a well-designed directive or pipe?
**Expected Answer:** One clear responsibility, a small public API, predictable behavior, no unnecessary global dependencies, and easy testability.

### 3. When should logic remain a plain TypeScript function instead of becoming a directive or pipe?
**Expected Answer:** When it has no template-binding or host-behavior need and is simpler as an ordinary reusable function.

### 4. Why should you avoid expensive computations inside templates or pipes?
**Expected Answer:** Presentation transformations run as part of rendering, so expensive repeated calculations can hurt rendering performance.

### 5. What should you do if a transformation is expensive or business-critical rather than hiding it in a pipe?
**Expected Answer:** Compute and own the value where it belongs (such as a service or component state) instead of relying on a pipe to solve the performance or ownership problem.

### 6. What is over-abstraction with directives and pipes, and why is it a problem?
**Expected Answer:** Creating unnecessary directives or pipes for logic that does not need reuse, which adds indirection and complexity without real benefit.

### 7. What is a common mistake when refactoring logic into directives and pipes?
**Expected Answer:** Extracting an abstraction that does not have a genuine reuse need, or mixing business logic into what should be a presentation-only directive or pipe.

### 8. JobHub scenario: reviewing ten pieces of UI logic in the Job Portal, how would you classify each as component, directive, pipe, function, or service?
**Expected Answer:** Classify by asking whether it owns UI structure (component), enhances a host element (directive), transforms a display value (pipe), needs no template binding (function), or owns shared state/behavior (service).

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not memorize syntax alone. Explain why the pattern fits the problem and which layer owns the responsibility.
