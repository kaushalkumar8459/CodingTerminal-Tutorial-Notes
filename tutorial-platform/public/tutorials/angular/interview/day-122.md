# Day 122 — Login, Logout and Session State

## Interview Goal
Implement predictable login/logout behavior and represent session state explicitly.

## Level 1 — Basic Questions
1. What happens during login?
2. What happens during logout?
3. What is current-user state?
4. Why should logout clear application state?
5. What is session expiry?

## Level 2 — Understanding
1. Why should login state not be represented only by the presence of a username in the UI?
2. What should happen to protected data after logout?
3. How should the application handle a failed login?
4. Why can logout require a backend request in some architectures?
5. How should a session-expired state differ from an ordinary login failure?

## Level 3 — Practical
1. Build typed login and logout methods.
2. Model authenticated user state with Signals.
3. Expose computed authentication status.
4. Clear sensitive feature state on logout.
5. Design a session-expiry transition.

## JobHub Scenarios
1. A recruiter logs out while the job editor is open. What state should be cleared?
2. Login succeeds but the dashboard API returns 401. What could have happened?
3. A session expires while browsing jobs. Should public job search remain available?
4. A logout request fails because the network is unavailable. What should the UI do?

## Interviewer Follow-Ups
- Why use a computed authentication status?
- What state belongs in AuthService versus feature stores?
- How would you test logout cleanup?
- How should multiple browser tabs affect session state?

## Coding Question
Create an AuthService with typed session state and login/logout methods using modern Angular Signals.

## Debugging Scenario
The UI says "Logged out" but previously loaded recruiter data remains visible after logout. Identify the state-cleanup problem.

## Common Interview Traps
- Clearing only the current-user signal.
- Leaving protected feature state in memory.
- Assuming logout is always purely client-side.
- Treating session expiry as the same as invalid credentials.

## Project Connection — JobHub
Session state controls access to candidate, recruiter, and admin experiences.

## Quick Revision
Login establishes session state; logout and expiry must also clean up protected application state.

## Interview Readiness
You are ready when you can describe every meaningful transition in the session lifecycle.
