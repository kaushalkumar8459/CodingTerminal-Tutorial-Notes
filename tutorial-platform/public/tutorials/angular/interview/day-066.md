# Day 66 Interview Questions — Service Responsibilities and Facade Design

## Interview Goal
Understand focused service responsibilities and when a feature facade simplifies Angular architecture.

## Interview Questions

### 1. What is a focused service?
**Expected Answer:** A service with a clear responsibility and a limited reason to change.

### 2. What is a facade service?
**Expected Answer:** A feature-facing API that coordinates state, data access, and business operations while hiding implementation details.

### 3. Why use a facade?
**Expected Answer:** It reduces component coupling to stores and lower-level services.

### 4. Should every feature have a facade?
**Expected Answer:** No. A facade is useful when orchestration complexity justifies it.

### 5. What belongs in a data-access service?
**Expected Answer:** API communication and deliberate mapping at the backend boundary.

### 6. What is a facade anti-pattern?
**Expected Answer:** A giant facade exposing every endpoint and every piece of application state.

### 7. JobHub scenario
**Expected Answer:** If JobSearchPage coordinates search, filters, pagination, loading, and API operations, a focused search facade can simplify the component.

## Interviewer Follow-Ups
- How does a facade improve testing?
- Where should mapping happen?
- How do you prevent facade growth?
- When is direct service injection simpler?

## Common Interview Trap
A facade is an architectural tool, not a mandatory layer for every component.

## Interview Readiness
