# Day 62 Interview Questions — Component and Route-Level Providers

## Interview Goal
Understand component-level and route-level provider scopes and when each is appropriate.

## Interview Questions

### 1. What is a component-level provider?
**Expected Answer:** A provider registered on a component creates a dependency scope associated with that component and its descendants.

### 2. What is a route-level provider?
**Expected Answer:** A provider configured on a route makes the dependency available within that route's injector scope.

### 3. Why use narrower provider scopes?
**Expected Answer:** They make ownership explicit and prevent state that should be isolated from becoming accidentally global.

### 4. Can child components resolve a component-provided service?
**Expected Answer:** Yes, descendants can resolve it through Angular's injector hierarchy.

### 5. What is a common provider-scope mistake?
**Expected Answer:** Creating separate instances when consumers actually need shared state, or making isolated feature state root-scoped.

### 6. When is route-level state useful?
**Expected Answer:** When state or services belong to one route-based feature and should not become application-wide.

### 7. How would you test scoped services?
**Expected Answer:** Verify that consumers within the intended scope share the expected instance and isolated scopes receive distinct instances when required.

### 8. JobHub scenario
**Expected Answer:** Recruiter create-job draft state can be scoped to the create-job route so it remains isolated from unrelated features.

## Interviewer Follow-Ups
- What changes if the service is provided in root?
- Who owns this service instance?
- How does injector hierarchy affect the result?
- What would you choose for application-wide authentication state?

## Common Interview Trap
Do not choose provider scope from habit. Choose it from ownership, sharing requirements, and lifecycle.
