# Day 127 — Authentication Errors and Session Expiry

## Interview Goal
Design graceful behavior when authentication fails, expires, or becomes invalid.

## Level 1 — Basic Questions
1. What is session expiry?
2. What is the difference between invalid credentials and an expired session?
3. What does HTTP 401 commonly indicate?
4. What is the difference between 401 and 403 at a high level?
5. Why should users receive actionable authentication feedback?

## Level 2 — Understanding
1. What should happen when the session expires during an API request?
2. How should the application avoid redirecting repeatedly?
3. When should the user see a login screen versus an access-denied screen?
4. Why should unsaved work be considered during session expiry?
5. How can the application preserve safe navigation context?

## Level 3 — Practical
1. Model session-expired state.
2. Handle a 401 through the HTTP layer.
3. Redirect to login once.
4. Preserve a safe return URL.
5. Clear protected state after session invalidation.

## JobHub Scenarios
1. A recruiter spends 20 minutes editing a job and the session expires. What should the UX consider?
2. A candidate receives 403 when trying to publish a job. What does that communicate differently from 401?
3. Multiple API calls fail after session expiry. How should the app avoid multiple login redirects?
4. A session expires on an admin screen. What data must be cleared?

## Interviewer Follow-Ups
- 401 versus 403?
- How would you preserve unsaved form data safely?
- Where should redirect coordination live?
- How would you test concurrent expiry events?

## Coding Question
Design a session-expiry handler that clears protected state and redirects to login without creating a redirect loop.

## Debugging Scenario
Five failed API requests create five login navigations. Identify the missing coordination mechanism.

## Common Interview Traps
- Treating 401 and 403 as identical.
- Losing all unsaved work without considering recovery.
- Redirecting from every interceptor independently.
- Leaving protected data in memory after logout.

## Project Connection — JobHub
Session-expiry handling connects authentication, forms, HTTP errors, routing, and state management.

## Quick Revision
Authentication failure handling is a coordinated application state transition, not merely an HTTP error message.

## Interview Readiness
You are ready when you can design a single, recoverable session-expiry flow.
