# Day 125 — Authentication Interceptors and Token Flow

## Interview Goal
Understand how authenticated HTTP requests interact with Angular interceptors and session lifecycle.

## Level 1 — Basic Questions
1. Why might an interceptor attach authentication information?
2. What is a token-based authentication flow?
3. What happens when an authenticated API returns 401?
4. Why should token handling be centralized?
5. What is token refresh at a high level?

## Level 2 — Understanding
1. Describe a request flow from an authenticated component to a protected API.
2. What should an interceptor do when no session exists?
3. Why can blindly retrying a 401 create loops?
4. Why should refresh logic be designed separately from ordinary API calls?
5. What should happen if refresh fails?

## Level 3 — Practical
1. Build a conditional authentication interceptor.
2. Exclude public requests where required.
3. Detect authentication failures.
4. Coordinate session-expiry handling.
5. Avoid duplicate refresh attempts.

## JobHub Scenarios
1. Ten requests fail with 401 at the same time. How could a naive refresh implementation create problems?
2. A public job-search API returns 401 unexpectedly. What should the interceptor do?
3. Refresh fails. How should the application transition the user back to authentication?
4. A request is retried after refresh but still returns 401. What should stop the retry loop?

## Interviewer Follow-Ups
- What is the difference between access and refresh tokens?
- Where should refresh tokens be stored?
- Should every 401 trigger refresh?
- How would you test concurrent 401 handling?

## Coding Question
Design an interceptor flow that handles authenticated requests and transitions to session expiry without infinite retries.

## Debugging Scenario
An application enters an infinite loop after a 401 response. Identify possible interceptor retry and refresh mistakes.

## Common Interview Traps
- Infinite 401 retry loops.
- Refreshing public requests.
- Duplicating auth logic in services.
- Treating token storage as a purely frontend security decision.

## Project Connection — JobHub
The auth interceptor connects session state to the HTTP layer used by protected job operations.

## Quick Revision
Authentication interceptors coordinate transport-level identity handling; they do not replace backend authorization.

## Interview Readiness
You are ready when you can reason about 401, refresh, retry, and session-expiry transitions.
