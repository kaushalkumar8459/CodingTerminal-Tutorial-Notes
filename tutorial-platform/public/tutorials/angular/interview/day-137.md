# Day 137 — Job Creation and Editing

## Interview Goal
Explain and apply the architecture concepts from this capstone day in a production Angular application.

## Level 1 — Basic Questions
1. What is the main problem this topic solves in a growing Angular application?
2. Which Angular concepts from earlier modules does this topic depend on?
3. What responsibilities should remain separate?
4. Why does strict typing improve this design?

## Level 2 — Understanding
1. Explain the trade-offs involved in the design.
2. Compare a simple implementation with an enterprise-scale implementation.
3. What belongs to the UI, feature, service, state, and API layers?
4. How would you keep the design testable?

## Level 3 — Practical
1. Design the solution for JobHub using standalone components and modern Angular APIs.
2. Identify the state, data flow, and failure states involved.
3. Explain how you would structure the TypeScript contracts.
4. Describe how you would prevent unnecessary coupling.

## JobHub Scenarios
Production Reactive Forms for create/edit flows, typed controls, cross-field validation, server validation, duplicate submission prevention, and unsaved changes. Practical questions: design job fields; validate salary ranges; map backend validation errors; handle concurrent edits and drafts. Coding: create a typed Job form with cross-field salary validation. Debugging: diagnose stale edit values when switching records.

## Interviewer Follow-Ups
- What would you change if JobHub grew from a small application to a multi-team enterprise product?
- How would you test this design?
- What failure modes would you expect in production?
- Which responsibility should remain on the backend?

## Coding Question
Implement a small, strictly typed version of the core design from this day. Prefer standalone Angular APIs, input/output signals where appropriate, inject(), and modern control flow.

## Debugging Scenario
A feature works initially but becomes difficult to maintain because UI logic, API calls, state, and authorization have become tightly coupled. Explain how you would isolate responsibilities and diagnose the dependency problem.

## Common Interview Traps
- Over-engineering before there is a real problem.
- Using any instead of strict domain types.
- Making every value global state.
- Treating frontend behavior as the backend security boundary.
- Mixing reusable UI with business-specific logic.

## Project Connection — JobHub
This day strengthens the production architecture of the JobHub capstone and connects earlier Angular fundamentals with enterprise implementation decisions.
