# Day 14 Interview Questions — Template Expressions and Best Practices

## Interview Goal
Be able to explain **Template Expressions and Best Practices**, write the relevant Angular code, discuss trade-offs, and apply it to a realistic JobHub feature.

## Interview Questions

### 1. What is an Angular template expression?
**Expected Answer:** It reads component state or calculates a display value using Angular template expression syntax.

### 2. Can templates contain arbitrary JavaScript statements?
**Expected Answer:** No. Angular templates use a constrained expression syntax rather than arbitrary JavaScript statements.

### 3. Why keep templates simple?
**Expected Answer:** Simple templates are easier to read, test, maintain, and reason about during rendering.

### 4. Why avoid side effects in templates?
**Expected Answer:** Rendering should describe UI state, not mutate application state or perform network operations.

### 5. When can computed() help template logic?
**Expected Answer:** It can hold memoized derived state that updates from signal dependencies.

### 6. How should expensive calculations be handled?
**Expected Answer:** Move them into appropriate derived state, view models, or services instead of repeating expensive work during rendering.

### 7. What is a common template performance mistake?
**Expected Answer:** Calling expensive methods repeatedly during rendering.

### 8. How should optional data be rendered?
**Expected Answer:** Use explicit null-safe access and control-flow states so missing data has intentional UI behavior.

### 9. JobHub scenario: application status depends on several fields. Where should the logic live?
**Expected Answer:** Prefer a typed view model or computed derived state rather than a large conditional expression in the template.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not memorize syntax alone. Explain **why** the pattern fits the UI state and which layer owns the underlying data.
