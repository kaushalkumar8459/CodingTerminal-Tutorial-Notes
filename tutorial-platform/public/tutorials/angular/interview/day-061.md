# Day 61 Interview Questions — Provider Scope and Service Lifetimes

## Interview Goal
Understand Angular's injector hierarchy, provider scope, service instance sharing, and how lifetime decisions affect application architecture.

## Interview Questions

### 1. What is an Angular injector?
**Expected Answer:** An injector resolves dependencies and creates or retrieves the instances requested by Angular components, services, routes, and other injectable consumers.

### 2. What does `providedIn: 'root'` generally mean?
**Expected Answer:** The service is registered with the root injector and is normally shared across the application.

### 3. Why would you use a component-level provider?
**Expected Answer:** To create a dependency instance scoped to that component's injector rather than sharing the root instance.

### 4. What is the practical effect of provider scope?
**Expected Answer:** It determines which consumers can resolve a dependency from that injector hierarchy and how instances are shared.

### 5. Can two components have separate service instances?
**Expected Answer:** Yes, if the service is provided in each component's injector scope.

### 6. Why does service lifetime matter?
**Expected Answer:** It affects state sharing, resource ownership, cleanup, and whether multiple consumers see the same instance.

### 7. What is a common provider-scope mistake?
**Expected Answer:** Using root scope for state that should be isolated to a feature or component.

### 8. How would you decide service scope?
**Expected Answer:** Start from state or resource ownership: application-wide services can be root-scoped, while isolated feature or component state can use narrower providers.

### 9. JobHub scenario: each JobEditor should maintain independent draft state. What scope fits?
**Expected Answer:** Provide the draft-state service at the appropriate editor or feature boundary so each editor gets its own instance.

## Interviewer Follow-Ups
- Why did you choose this provider scope?
- What happens if the service is moved to root?
- How would you test instance isolation?
- How does provider scope affect state ownership?
- What would you choose for an enterprise feature?

## Common Interview Trap
Do not assume every service should be provided in root. Choose scope based on ownership and intended sharing.
