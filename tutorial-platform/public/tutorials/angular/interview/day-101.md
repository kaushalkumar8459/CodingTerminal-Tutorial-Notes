# Day 101 — Custom Form Controls and ControlValueAccessor

## Interview Goal
Understand how Angular integrates reusable custom UI controls with Reactive Forms.

## Level 1 — Basic Questions
1. What is a custom form control in Angular?
2. What problem does `ControlValueAccessor` solve?
3. What are the main methods of `ControlValueAccessor`?
4. Why does a custom control need to communicate value changes to Angular Forms?
5. What is the difference between a form control's value and its disabled state?

## Level 2 — Understanding
1. Explain `writeValue()`, `registerOnChange()`, `registerOnTouched()`, and `setDisabledState()`.
2. When should a custom control call the registered change callback?
3. When should it call the touched callback?
4. Why should `writeValue()` update the UI without emitting a new form value?
5. How is a custom control connected to Angular Forms infrastructure?

## Level 3 — Practical
1. Build a reusable star-rating control for `FormControl<number>`.
2. Build a reusable job-skill selector.
3. Support disabled state correctly.
4. Display validation state from the parent form.
5. Keep the control strongly typed without `any`.

## Level 4 — JobHub Scenarios
1. JobHub needs a reusable Salary Range control. How would you integrate it with Reactive Forms?
2. A LocationPicker updates visually, but the parent form value never changes. What would you inspect?
3. A custom control becomes touched immediately when the form loads. What could be wrong?
4. Resetting a form does not reset a custom control. Which CVA behavior should you investigate?

## Level 5 — Interviewer Follow-Ups
- Why is `ControlValueAccessor` an adapter pattern?
- What happens if `registerOnChange()` is implemented incorrectly?
- How would you test a custom form control?
- When would you use a normal component with an output instead of CVA?

## Coding Question
Create a typed `JobTypeSelectorComponent` supporting `full-time | part-time | contract` and use it with a `FormControl`.

## Debugging Scenario
A custom control calls its change callback from `writeValue()`, causing unexpected form updates. Identify and fix the design issue.

## Common Interview Traps
- Treating `writeValue()` as a user-change event.
- Forgetting touched state.
- Ignoring disabled state.
- Using `any` for form values.

## Project Connection — JobHub
Reusable controls such as salary range, location, experience level, and job type can be shared across candidate and recruiter forms.

## Quick Revision
CVA connects a custom UI component to Angular Forms through value, touched, and disabled-state callbacks.

## Self-Assessment
Can you build a custom control that behaves like a native Angular form control?

## Interview Readiness
You are ready when you can explain the CVA lifecycle and implement a typed custom control without copying a recipe blindly.
