# Day 275 — Shared UI, Services and Authentication

## Interview Goal
Explain and apply this Micro Frontend concept in Angular using strict TypeScript, standalone components, clear application boundaries, and production-oriented Native Federation practices.

> **Tooling note:** Angular Native Federation is third-party tooling. Configuration and APIs can vary by package/version, so interview answers should distinguish Angular platform concepts from Native Federation-specific configuration.

## Level 1 — Basic Questions
1. What problem does this topic solve?
2. What is the simplest example?
3. Why is it useful in a Micro Frontend architecture?
4. What common beginner mistake should be avoided?

## Level 2 — Understanding
1. Explain the host/remote/runtime flow step by step.
2. Compare the approach with a monolith or another MFE integration strategy.
3. What are the deployment, performance, security, and maintainability implications?
4. When should you avoid this approach?

## Level 3 — Practical
1. How would you apply it to JobHub?
2. Who owns each boundary and contract?
3. How would you keep configuration and contracts strongly typed?
4. How would you test failure, version mismatch, navigation, and deployment scenarios?

## JobHub Scenarios
Deciding what should be shared across MFEs, authentication/session boundaries, shared UI contracts, and avoiding hidden cross-remote state. JobHub scenarios: common design system and authenticated shell. Coding: design safe platform contracts. Debugging: diagnose duplicated auth state or tightly coupled services.

## Interviewer Follow-Ups
- Why is this an MFE boundary instead of a normal Angular feature boundary?
- What should the host own versus the remote?
- How would you prevent remote-to-remote coupling?
- What happens if a remote is unavailable or deployed independently?
- How would you handle version compatibility and runtime configuration?
- What security assumptions exist between independently deployed applications?

## Coding Question
Design or implement a focused JobHub MFE example based on this day's concept using standalone Angular and strict TypeScript. Avoid `any`, direct access to remote internals, and unnecessary shared state.

## Debugging Scenario
A JobHub host cannot load a remote, a route is missing, shared dependencies conflict, runtime configuration points to the wrong environment, cross-MFE communication fails, or a remote deployment serves stale assets. Explain how you would reproduce, inspect, diagnose, and fix the issue.

## Common Interview Traps
- Treating Native Federation APIs as Angular core APIs.
- Sharing everything between host and remotes.
- Letting remotes depend on host internals.
- Assuming shared dependencies eliminate all version-compatibility concerns.
- Hard-coding remote URLs into application code.
- Using cross-MFE events as an untyped global event bus.
- Ignoring remote failure and cache invalidation.
- Choosing MFE solely because an application is large.
