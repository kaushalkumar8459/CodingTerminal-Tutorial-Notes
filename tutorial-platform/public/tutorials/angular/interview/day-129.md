# Day 129 — Mini Project: Authenticated Job Portal

## Interview Goal
Combine authentication, authorization, routing, HTTP, and shell UX into one realistic feature.

## Level 1 — Basic Questions
1. What features should an authenticated job portal contain?
2. Which routes are public?
3. Which routes require authentication?
4. Which actions require specific permissions?
5. What should happen when the session expires?

## Level 2 — Understanding
1. Describe the complete login-to-dashboard flow.
2. Where should authentication state live?
3. Where should permission checks live?
4. Where should authentication headers be added?
5. Which parts must be enforced by the backend?

## Level 3 — Practical
1. Build login and logout.
2. Protect authenticated routes.
3. Add role/permission-aware navigation.
4. Add an authenticated app shell.
5. Add session-expiry handling.
6. Connect protected APIs through an auth-aware HTTP layer.

## JobHub Scenarios
1. Candidate and recruiter share job-search screens but have different actions. How should authorization work?
2. A recruiter can create jobs but cannot publish them. How should UI and backend coordinate?
3. The session expires while the user is submitting an application. How should the workflow recover?
4. A user manually requests an admin API. What must prevent unauthorized access?

## Interviewer Follow-Ups
- What would you test end-to-end?
- Which concerns belong in guards, interceptors, services, and backend APIs?
- How would you handle multiple simultaneous 401 responses?
- How would you explain this architecture in an interview?

## Coding Question
Implement the core authenticated Job Portal flow with typed session state, route guards, permission-aware navigation, and protected API access.

## Debugging Scenario
A candidate can navigate to the recruiter area after changing a local role value, but recruiter API calls fail. Explain why frontend role checks are not sufficient.

## Common Interview Traps
- Putting all auth logic in route guards.
- Treating hidden UI as security.
- Duplicating token handling.
- Forgetting session-expiry and logout cleanup.

## Project Connection — JobHub
This mini project closes the Authentication module and becomes the security foundation for the complete Angular capstone.

## Quick Revision
A secure Angular application coordinates identity, navigation, permissions, HTTP, state, and backend enforcement.

## Interview Readiness
You are ready when you can draw the authentication flow and explain every boundary.
