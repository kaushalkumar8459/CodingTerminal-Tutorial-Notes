# Day 15 Interview Questions — Interactive Profile UI

## Interview Goal
Be able to explain **Interactive Profile UI**, write the relevant Angular code, discuss trade-offs, and apply it to a realistic JobHub feature.

## Interview Questions

### 1. What should this mini project demonstrate?
**Expected Answer:** Templates, bindings, events, conditional rendering, and user-driven state working together in one feature.

### 2. How would Edit Profile work?
**Expected Answer:** An event handler changes edit state and the template renders the editing UI.

### 3. How would Save appear only during editing?
**Expected Answer:** Use an @if block around the editing actions.

### 4. How would you display a calculated completion percentage?
**Expected Answer:** Keep the value as typed derived state and bind it to the UI.

### 5. How should transient UI state differ from profile data?
**Expected Answer:** State such as isEditing belongs to UI state; persisted fields belong to the profile model.

### 6. What would you test?
**Expected Answer:** Initial rendering, edit/save/cancel behavior, displayed values, and important accessibility attributes.

### 7. How could an avatar fallback be rendered?
**Expected Answer:** Use conditional rendering to show the image or initials when the image is unavailable.

### 8. How could accessibility state be bound?
**Expected Answer:** For example, bind aria-expanded with an attribute binding for an expandable section.

### 9. JobHub scenario: a user cancels profile editing. What should happen?
**Expected Answer:** Discard the draft UI state and restore the previously persisted profile values without accidentally mutating the saved model.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not memorize syntax alone. Explain **why** the pattern fits the UI state and which layer owns the underlying data.
