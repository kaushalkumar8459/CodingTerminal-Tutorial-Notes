# Day 159 — Template Literal Types

## Interview Goal
Explain and apply this TypeScript concept in modern Angular applications using strict typing.

## Level 1 — Basic Questions
1. What problem does this TypeScript feature solve?
2. Why is it useful in Angular applications?
3. What is the simplest example of it?
4. What common beginner mistake should be avoided?

## Level 2 — Understanding
1. Explain how the type system represents the concept.
2. Compare it with the closest alternative.
3. When should you use it and when should you keep the type simpler?
4. What does it guarantee at compile time, and what does it not guarantee at runtime?

## Level 3 — Practical
1. How would you apply this concept to JobHub?
2. How would you keep the resulting types readable?
3. How would you test code that depends on these types?
4. How would you avoid weakening the design with `any` or unnecessary casts?

## JobHub Scenarios
Template literal types, string unions, key patterns, event names, and typed permission/action identifiers. JobHub scenarios: model permissions such as jobs.read and jobs.create and derive action names safely. Coding: create a typed permission naming pattern. Debugging: reject an invalid string at compile time without runtime regex.

## Interviewer Follow-Ups
- How does this feature interact with Angular templates?
- How would you use it in a multi-team codebase?
- What maintenance problem could an overly complex type create?
- When would you choose a simpler type instead?

## Coding Question
Implement a small JobHub example using this day's TypeScript concept. Keep the solution strictly typed and production-oriented.

## Debugging Scenario
A developer fixes a TypeScript error by adding `any` or an unsafe assertion. Explain how you would identify the underlying type problem and preserve type safety.

## Common Interview Traps
- Confusing compile-time types with runtime validation.
- Using advanced type features when a simple interface is clearer.
- Reaching for `any` instead of narrowing or modeling the domain.
- Writing clever types that the team cannot maintain.

## Project Connection — JobHub
Use this concept to strengthen JobHub's API contracts, domain models, forms, state, and reusable utilities.

## Quick Revision
Review the syntax, use case, trade-offs, JobHub scenario, and debugging strategy.

## Interview Readiness
You are ready when you can explain the feature, write a strict example, and justify why the chosen type design is maintainable.
