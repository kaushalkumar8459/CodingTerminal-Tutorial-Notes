# Day 121 — Authentication Architecture

## Interview Goal
Understand how authentication fits into a modern Angular application without treating the frontend as the security boundary.

## Level 1 — Basic Questions
1. What are the main parts of an authentication system?
2. What is the role of the frontend during login?
3. What is the role of the backend during authentication?
4. What is session state?
5. Why should authentication architecture be designed before building login UI?

## Level 2 — Understanding
1. Describe the flow from login form submission to an authenticated application.
2. Where should identity information come from?
3. Why should the frontend not decide whether credentials are valid?
4. What should happen when authentication fails?
5. How should an application represent an anonymous user?

## Level 3 — Practical
1. Design an AuthService boundary.
2. Define typed authenticated-user state.
3. Define login and logout responsibilities.
4. Design application bootstrap behavior for an existing session.
5. Separate authentication state from authorization checks.

## JobHub Scenarios
1. JobHub supports Candidate, Recruiter, and Admin users. How would you model identity?
2. The browser reloads after login. How should the application restore session state?
3. Login succeeds but loading the current user fails. What state should the application enter?
4. A user opens a protected URL before authentication state finishes loading. How should navigation behave?

## Interviewer Follow-Ups
- Authentication service versus auth store?
- Where should current-user data come from?
- Why is backend identity authoritative?
- How would you test authentication bootstrap?

## Coding Question
Design typed authentication states for anonymous, authenticating, authenticated, and authentication-error conditions.

## Debugging Scenario
The application briefly renders the protected dashboard before redirecting an anonymous user. Identify the missing authentication bootstrap state.

## Common Interview Traps
- Treating a local boolean as proof of authentication.
- Mixing authentication and authorization.
- Reading user roles from untrusted client state as the final authority.
- Ignoring application startup state.

## Project Connection — JobHub
This architecture becomes the foundation for login, guards, permissions, interceptors, and authenticated feature shells.

## Quick Revision
Authentication architecture coordinates identity, session state, bootstrap, login, logout, and failure handling.

## Interview Readiness
You are ready when you can explain the authentication lifecycle before discussing individual Angular APIs.
