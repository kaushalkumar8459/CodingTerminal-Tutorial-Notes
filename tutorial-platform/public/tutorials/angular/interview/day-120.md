# Day 120 — Why Authentication & Authorization?

## Interview Goal
Understand the difference between authentication and authorization and how they shape an Angular application's security architecture.

## Level 1 — Basic Questions
1. What is authentication?
2. What is authorization?
3. How are authentication and authorization different?
4. Why can a frontend route guard not provide complete security?
5. What is a session?

## Level 2 — Understanding
1. Describe a typical login flow from browser to backend.
2. Why must backend authorization be authoritative?
3. What is the purpose of a session or access token?
4. Why should protected UI routes still be backed by protected APIs?
5. What is the difference between identity and permission?

## Level 3 — Practical
1. Design a login/logout flow for JobHub.
2. Model authenticated user state.
3. Protect candidate, recruiter, and admin routes appropriately.
4. Design an authentication service boundary.
5. Define how session expiry should affect the UI.

## JobHub Scenarios
1. A user manually navigates to an admin URL. What should the frontend do, and what must the backend do?
2. A candidate changes the URL from candidate to recruiter. What security assumptions are unsafe?
3. A session expires while the user is editing a job. What recovery flow would you design?
4. A user is authenticated but lacks permission to publish jobs. How should the application represent that?

## Level 5 — Interviewer Follow-Ups
- Can route guards secure an API?
- Where should role and permission checks happen?
- What is the difference between authentication state and authorization state?
- How would you test authentication architecture?

## Coding Question
Design typed authentication state for JobHub, including anonymous, authenticated, and session-expired states.

## Debugging Scenario
An admin page is hidden by the UI but its API endpoint can still be called directly. Explain the missing security boundary.

## Common Interview Traps
- Treating route guards as security.
- Confusing login with authorization.
- Trusting client-side role values.
- Storing sensitive secrets in frontend code.

## Project Connection — JobHub
Authentication and authorization become the next major architectural layer after HTTP integration.

## Quick Revision
Authentication establishes identity; authorization determines permissions; backend enforcement is the real security boundary.

## Interview Readiness
You are ready when you can explain the complete identity-to-permission flow without relying on frontend checks as security.
