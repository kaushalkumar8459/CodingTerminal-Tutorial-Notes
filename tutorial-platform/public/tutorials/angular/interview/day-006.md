# Day 6 — Angular Application Flow: Interview Questions

## Topic

**bootstrapApplication, root component, configuration, template rendering, browser flow**

## Interview Goal

Trace an Angular application from startup to rendered UI.

---

## Interview Questions

### Q1. What happens when an Angular application starts?

**Expected Answer:**
The browser loads the application bundle, the Angular entry point runs, the application is bootstrapped, and Angular renders the component tree.

### Q2. What is `bootstrapApplication`?

**Expected Answer:**
It is the modern Angular API used to bootstrap a standalone root component with application providers/configuration.

### Q3. What is the role of the root component?

**Expected Answer:**
It is the starting point of the application's component tree and provides the initial UI.

### Q4. What is the relationship between `main.ts` and `app.config.ts`?

**Expected Answer:**
The entry point bootstraps the application and can supply application configuration/providers defined in the configuration file.

### Q5. How does a component template become visible in the browser?

**Expected Answer:**
Angular creates the component and renders its template into the application's DOM.

### Q6. Why is understanding application flow useful?

**Expected Answer:**
It helps developers trace startup, configuration, rendering and runtime problems instead of treating Angular as a black box.

### Q7. Scenario: The browser opens but the expected Angular UI is missing. What would you inspect?

**Expected Answer:**
Check browser/terminal errors, bootstrap configuration, root component/template and the HTML host element.

### Q8. Practical: Trace your Day 2 project from `main.ts` to the first visible component.

**Expected Answer:**
The learner should describe the startup path at a high level without needing framework internals.

- What problem does it solve?
- How would you use it in a real project?
- What common mistake can a beginner make with it?
- How would you debug a problem involving this concept?

```text
Definition → Why → Example → Project usage → Trade-off / limitation
```
