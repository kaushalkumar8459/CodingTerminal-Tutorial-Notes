# Day 208 — Angular Material Fundamentals and Theming

## Interview Goal
Explain and apply this Angular CDK, Material, responsive UI, or accessibility concept using modern Angular and production-quality UI patterns.

## Level 1 — Basic Questions
1. What problem does this topic solve?
2. What is the simplest example?
3. Why is it useful in Angular applications?
4. What common beginner mistake should be avoided?

## Level 2 — Understanding
1. Explain how the feature works and its lifecycle.
2. Compare it with a custom implementation or the closest Angular alternative.
3. What are the usability, accessibility, performance, and maintainability implications?
4. When should you avoid this approach?

## Level 3 — Practical
1. How would you apply it to JobHub?
2. How would you keep the implementation reusable and strongly typed?
3. How would you test keyboard, focus, interaction, and responsive behavior?
4. How would you handle cleanup and failure states?

## JobHub Scenarios
Material component architecture, importing components, typography, density, theming concepts, and integrating Material with an existing design system. JobHub scenarios: forms, navigation, dialogs, tables, and status UI. Coding: build a small Material-based feature. Debugging: diagnose inconsistent theme or component configuration.

## Interviewer Follow-Ups
- Why did you choose CDK, Material, or a custom implementation?
- How would you make the interaction keyboard accessible?
- How would you manage focus and lifecycle correctly?
- How would you keep UI behavior separate from business logic?
- What would you consider for mobile and responsive layouts?

## Coding Question
Implement a small JobHub UI example based on this day's concept using standalone Angular components and strict TypeScript. Prefer semantic HTML and accessible interaction patterns. Avoid `any`.

## Debugging Scenario
A JobHub UI works with a mouse but has focus, keyboard, responsive, overlay, lifecycle, or screen-reader problems. Explain how you would reproduce, inspect, diagnose, and fix the issue.

## Common Interview Traps
- Treating accessibility as an optional final step.
- Adding ARIA where semantic HTML already provides the correct behavior.
- Ignoring keyboard and focus management.
- Creating overlays without lifecycle cleanup.
- Mixing UI-library APIs directly into business logic.
- Assuming responsive design means only changing CSS.

## Project Connection — JobHub
Apply today's concept to JobHub search, forms, navigation, recruiter workflows, admin dashboards, dialogs, menus, or responsive layouts.

## Quick Revision
Review the core API, lifecycle, accessibility requirements, responsive behavior, design trade-offs, testing strategy, and JobHub scenario.

## Interview Readiness
You are ready when you can explain not only how the UI works, but also how it remains accessible, responsive, reusable, and maintainable.
