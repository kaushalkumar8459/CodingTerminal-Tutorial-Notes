# Day 113 — HTTP Interceptors

## Interview Goal
Understand how Angular HTTP interceptors centralize cross-cutting request and response behavior.

## Level 1 — Basic Questions
1. What is an HTTP interceptor?
2. Why would an application use an interceptor?
3. What is the difference between request and response interception?
4. How are interceptors configured in a standalone Angular application?
5. Can an interceptor modify a request?

## Level 2 — Understanding
1. Explain the interceptor chain.
2. Why should authorization headers usually be centralized?
3. How can an interceptor add correlation IDs?
4. What should an interceptor avoid doing?
5. How can multiple interceptors work together?

## Level 3 — Practical
1. Create a functional interceptor.
2. Add an authorization header when appropriate.
3. Add request logging for development diagnostics.
4. Add a correlation/request ID.
5. Handle a common response or transport error consistently.

## JobHub Scenarios
1. Every protected API request needs authentication metadata. Where should it be added?
2. Public job-search endpoints must not receive protected-session headers. How would the interceptor decide?
3. A logging interceptor exposes sensitive data. What should change?
4. Two interceptors modify the same header. How would you reason about ordering and ownership?

## Interviewer Follow-Ups
- What is a functional interceptor?
- What is the difference between interceptors and API services?
- Can interceptors implement business logic?
- How would you test an interceptor?

## Coding Question
Implement an interceptor that conditionally adds an authentication header while preserving the immutable request model.

## Debugging Scenario
A token header is added twice. Identify possible interceptor-registration or cloning problems.

## Common Interview Traps
- Treating interceptors as global business logic.
- Logging tokens or sensitive payloads.
- Mutating requests instead of cloning them.
- Applying auth headers to every request without considering public endpoints.

## Project Connection — JobHub
Interceptors provide the platform-level HTTP pipeline for authentication, diagnostics, and consistent transport behavior.

## Quick Revision
Interceptors are best for cross-cutting HTTP concerns, not feature-specific business behavior.

## Interview Readiness
You are ready when you can explain why a concern belongs in an interceptor instead of an API service or component.
