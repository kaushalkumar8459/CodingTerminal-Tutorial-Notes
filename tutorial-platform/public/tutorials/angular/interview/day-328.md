# Day 328 — WebMCP Fundamentals

## Learning Goal
Learn WebMCP as an emerging browser-facing standard that lets web applications expose structured tools to AI agents. Clearly distinguish WebMCP from Angular CLI MCP. Coding: model a safe JobHub tool such as searchJobs. Treat the API as experimental.

## Core Concepts
1. What problem does this AI capability solve?
2. How does it relate to Angular's application and developer tooling?
3. What belongs in Angular, what belongs in the backend, and what belongs in the AI/tooling layer?
4. Which APIs are stable, experimental, or provider-specific?

## Practical Angular Questions
1. How would you implement this in a standalone Angular application?
2. How would you keep the design strongly typed?
3. How would you test the behavior without depending on a live model or agent?
4. How would you handle failures, latency, permissions, and unavailable AI services?

## JobHub Scenario
Design a realistic JobHub use case for today's topic. Prefer explicit tool contracts, narrow permissions, typed inputs/outputs, and clear separation between UI, application services, backend authorization, and AI infrastructure.

## Interview Questions
- What is the difference between AI-assisted development and an AI-powered application?
- What is MCP, and what problem does it solve?
- How is Angular CLI MCP different from WebMCP?
- Why should experimental APIs be isolated behind clear boundaries?
- Why must an AI tool not automatically become a security boundary?
- How would you prevent an AI agent from performing an unauthorized JobHub action?

## Coding Question
Implement a small typed Angular example related to today's topic. Use standalone APIs, `inject()`, signals where appropriate, and strict TypeScript. Do not use `any`.

## Debugging Scenario
An AI-generated Angular feature compiles but violates project architecture, exposes sensitive data, registers duplicate tools, uses an experimental API incorrectly, or performs an unauthorized action. Explain how you would inspect the generated code, verify the contract, reproduce the issue, fix it, and add regression coverage.

## Common Traps
- Treating AI output as trusted production code.
- Sending secrets or private data directly to a model from the browser.
- Giving an AI tool broader permissions than required.
- Confusing Angular CLI MCP with WebMCP.
- Treating experimental WebMCP APIs as stable Angular fundamentals.
- Skipping schema/input validation because an agent generated the request.
- Allowing the AI layer to bypass normal backend authorization.
- Building AI functionality where deterministic Angular logic is sufficient.

## Project Connection — JobHub
Use JobHub as the running example. AI may help developers build JobHub, while AI-powered JobHub features can assist candidates or recruiters. Keep these two concerns separate.

## Quick Revision
Review the AI problem, Angular boundary, MCP/tool contract, data flow, security model, testing strategy, and experimental/stable status.

## Interview Readiness
You are ready when you can explain the feature without hype, distinguish framework capabilities from third-party AI providers, write a typed implementation, and identify security and reliability risks.
