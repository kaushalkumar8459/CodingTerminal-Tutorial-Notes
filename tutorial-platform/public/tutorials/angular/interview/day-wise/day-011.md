# Day 11 Interview Questions — Attribute, Class and Style Binding

## Interview Goal
Be able to explain **Attribute, Class and Style Binding**, write the relevant Angular code, discuss trade-offs, and apply it to a realistic JobHub feature.

## Interview Questions

### 1. What is attribute binding?
**Expected Answer:** Use [attr.name] to dynamically set an HTML attribute. It is especially useful for attributes such as ARIA attributes.

### 2. Property binding vs attribute binding?
**Expected Answer:** Property binding updates a DOM property; attribute binding updates an HTML attribute. For example, [disabled] is a property binding while [attr.aria-label] is attribute binding.

### 3. How do you conditionally apply one class?
**Expected Answer:** Use [class.className] with a boolean expression.

### 4. How do you bind a style value?
**Expected Answer:** Use bindings such as [style.color] or [style.width.px] for dynamic style values.

### 5. How do you bind multiple classes?
**Expected Answer:** Use [class] with a string or suitable class map, or multiple individual class bindings.

### 6. Why use attr. for ARIA?
**Expected Answer:** ARIA values are HTML attributes, so [attr.aria-label] and similar bindings are appropriate.

### 7. What happens when an attribute binding evaluates to null?
**Expected Answer:** Angular removes the attribute, which is useful for optional attributes.

### 8. When should classes be preferred over inline styles?
**Expected Answer:** Prefer classes for reusable visual states; use styles for genuinely dynamic values.

### 9. JobHub scenario: mark urgent jobs visually. How?
**Expected Answer:** Keep isUrgent as typed state and bind a CSS class conditionally, while keeping visual rules in CSS.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not memorize syntax alone. Explain **why** the pattern fits the UI state and which layer owns the underlying data.
