# Day 18 Interview Questions — @for

## Interview Goal
Be able to explain **@for**, write the relevant Angular code, discuss trade-offs, and apply it to a realistic JobHub feature.

## Interview Questions

### 1. What does @for do?
**Expected Answer:** It repeats a template for every item in an iterable collection.

### 2. What does track do?
**Expected Answer:** It identifies items across collection changes so Angular can reuse DOM nodes.

### 3. Why prefer stable identity?
**Expected Answer:** Stable identity reduces unnecessary DOM recreation when items are updated or reordered.

### 4. How should jobs be tracked?
**Expected Answer:** Use a stable unique job identifier such as job.id.

### 5. What is $index?
**Expected Answer:** It is the current zero-based index exposed by the @for block.

### 6. Name other @for contextual values.
**Expected Answer:** Examples include $count, $first, $last, $even, and $odd.

### 7. When might tracking by index be acceptable?
**Expected Answer:** For genuinely static collections where item identity never changes, although stable item identity is generally preferable for dynamic data.

### 8. How do you optimize a large list?
**Expected Answer:** Use stable tracking, avoid unnecessary per-item calculations, consider pagination or virtualization when measurement shows it is needed.

### 9. JobHub scenario: jobs return in a different order after refresh. What should track use?
**Expected Answer:** Use job ID rather than array index so DOM identity follows the same job.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not memorize syntax alone. Explain **why** the pattern fits the UI state and which layer owns the underlying data.
