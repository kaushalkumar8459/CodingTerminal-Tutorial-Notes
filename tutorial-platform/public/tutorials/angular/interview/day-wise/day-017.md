# Day 17 Interview Questions — @if

## Interview Goal
Be able to explain **@if**, write the relevant Angular code, discuss trade-offs, and apply it to a realistic JobHub feature.

## Interview Questions

### 1. What does @if do?
**Expected Answer:** It conditionally renders a template block when its expression is truthy.

### 2. How do you add an alternative branch?
**Expected Answer:** Use @else.

### 3. Can you have multiple conditional branches?
**Expected Answer:** Yes, use @else if for mutually exclusive conditions.

### 4. Why is @if useful for UI states?
**Expected Answer:** It makes conditional rendering explicit and readable.

### 5. How can conditional rendering handle authentication UI?
**Expected Answer:** Use explicit authentication state to render authenticated or anonymous UI branches.

### 6. Why model loading and error separately?
**Expected Answer:** An empty initial collection should not automatically mean loading or error; explicit state avoids ambiguity.

### 7. What is a common @if anti-pattern?
**Expected Answer:** Deeply nested conditions containing business rules instead of presentation decisions.

### 8. How should retry logic be organized?
**Expected Answer:** The template displays the retry action; component or data-access code owns the retry operation.

### 9. JobHub scenario: show Retry only after a failed API request. What is the design?
**Expected Answer:** Track an explicit error state and conditionally render Retry with @if.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not memorize syntax alone. Explain **why** the pattern fits the UI state and which layer owns the underlying data.
