# Day 16 Interview Questions — Introduction to Angular Control Flow

## Interview Goal
Be able to explain **Introduction to Angular Control Flow**, write the relevant Angular code, discuss trade-offs, and apply it to a realistic JobHub feature.

## Interview Questions

### 1. Why use modern Angular control flow?
**Expected Answer:** Built-in blocks such as @if, @for, and @switch provide clear template control flow.

### 2. What are the main control-flow blocks?
**Expected Answer:** @if, @for, and @switch; @empty can provide an empty-state branch for @for.

### 3. How does block syntax differ from legacy structural directives?
**Expected Answer:** It uses built-in block syntax rather than directive syntax such as *ngIf and *ngFor.

### 4. Why learn conditional rendering before list rendering?
**Expected Answer:** It establishes the basic block model and UI-state thinking before handling collections.

### 5. Can control-flow blocks be nested?
**Expected Answer:** Yes, nested blocks are valid and useful for hierarchical UI states.

### 6. What is @empty?
**Expected Answer:** It defines UI for an empty collection rendered by @for.

### 7. Why is track important?
**Expected Answer:** It gives Angular stable item identity so DOM can be reused efficiently.

### 8. What is a control-flow anti-pattern?
**Expected Answer:** Putting complex business rules directly inside deeply nested template conditions.

### 9. JobHub scenario: show loading, error, empty, and success states. How?
**Expected Answer:** Model those states explicitly and use control-flow blocks to render each state intentionally.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not memorize syntax alone. Explain **why** the pattern fits the UI state and which layer owns the underlying data.
