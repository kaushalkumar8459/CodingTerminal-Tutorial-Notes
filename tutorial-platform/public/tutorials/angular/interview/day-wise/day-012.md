# Day 12 Interview Questions — Event Binding

## Interview Goal
Be able to explain **Event Binding**, write the relevant Angular code, discuss trade-offs, and apply it to a realistic JobHub feature.

## Interview Questions

### 1. What is event binding?
**Expected Answer:** It listens for an event and runs a template expression, such as (click) calling a component method.

### 2. What is $event?
**Expected Answer:** It is the event object supplied to an event handler.

### 3. How do you handle keyboard events?
**Expected Answer:** Use events such as keydown and Angular key-specific event syntax such as keydown.enter.

### 4. Why keep handlers small?
**Expected Answer:** Templates should remain readable; substantial business logic belongs in component or service code.

### 5. How do you type DOM events?
**Expected Answer:** Use specific types such as MouseEvent, KeyboardEvent, or SubmitEvent instead of any.

### 6. What is event bubbling?
**Expected Answer:** Many DOM events propagate from the target toward ancestors, so parent handlers may also receive them.

### 7. How do you prevent a default browser action?
**Expected Answer:** Call preventDefault() on the appropriate event when the behavior must be suppressed.

### 8. What is a common event-binding anti-pattern?
**Expected Answer:** Duplicating the same business logic across multiple event handlers.

### 9. JobHub scenario: search should happen on form submit, not only button click. What do you do?
**Expected Answer:** Handle the form submit event and centralize the search operation in one component method.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not memorize syntax alone. Explain **why** the pattern fits the UI state and which layer owns the underlying data.
