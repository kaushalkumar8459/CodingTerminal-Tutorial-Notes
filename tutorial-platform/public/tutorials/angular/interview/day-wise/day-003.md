# Day 3 — Angular Project Structure: Interview Questions

## Topic

**src, app, main.ts, app.config.ts, app.routes.ts, public, styles, angular.json, package.json, tsconfig**

## Interview Goal

Explain the important generated files without going deep into TypeScript.

---

## Interview Questions

### Q1. What is the purpose of the `src` folder?

**Expected Answer:**
It contains the application's source code and assets used to build the application.

### Q2. What is `main.ts` used for?

**Expected Answer:**
It is the application entry point that starts Angular and bootstraps the root application.

### Q3. What is `app.config.ts`?

**Expected Answer:**
It commonly contains application-level providers and configuration used during bootstrap.

### Q4. What is `app.routes.ts`?

**Expected Answer:**
It is commonly used to define the application's route configuration when routing is enabled.

### Q5. What is the purpose of the `public` folder?

**Expected Answer:**
It contains static assets that can be served as application assets without being treated as component source.

### Q6. What is `package.json`?

**Expected Answer:**
It describes project metadata, dependencies, scripts and package configuration.

### Q7. What is `angular.json`?

**Expected Answer:**
It contains Angular CLI workspace and project build, serve and related configuration.

### Q8. Why should a fresher avoid learning every configuration file deeply on Day 3?

**Expected Answer:**
The immediate goal is to understand how the application is organized; deeper tooling and TypeScript configuration can be learned when needed.

### Q9. Scenario: A developer changes `main.ts` and the application stops starting. How would you investigate?

**Expected Answer:**
Read the compile/runtime error, verify the bootstrap call and imports, and isolate the smallest change that caused the failure.

### Q10. Practical: Open a generated Angular project and explain the role of its five most important files.

**Expected Answer:**
The learner should explain the entry point, root application files, package configuration and CLI configuration in their own words.

## Interviewer Follow-Ups

Be prepared to answer these without memorizing definitions:

- Why is this concept needed at this point in an Angular application?
- What problem does it solve?
- How would you use it in a real project?
- What common mistake can a beginner make with it?
- How would you debug a problem involving this concept?

## Scenario Practice

**JobHub scenario:** Apply today's concept to the JobHub application. Explain the problem first, then identify the Angular feature that solves it. Do not introduce later concepts unless the scenario genuinely requires them.

## Common Interview Trap

Do not answer only with a definition. Follow the pattern:

```text
Definition → Why → Example → Project usage → Trade-off / limitation
```
