# Module 21 — SSR, SSG and Hydration

## Days 236–245

Learn Angular's server and hybrid rendering model, then understand how hydration makes server-rendered HTML interactive.

### Sequence

- Day 236 — CSR vs SSR vs SSG
- Day 237 — Angular SSR Setup and Application Architecture
- Day 238 — Server Routes and Render Modes
- Day 239 — Authoring Server-Compatible Angular Components
- Day 240 — Prerendering and Static Site Generation
- Day 241 — Hydration Fundamentals
- Day 242 — Hydration Constraints and Debugging
- Day 243 — Incremental Hydration and Event Replay
- Day 244 — SSR Data Transfer, Caching and Production Architecture
- Day 245 — Mini Project — Hybrid JobHub Website

### Learning principles

- Choose rendering mode per route and user need.
- Keep server and browser rendering structurally consistent.
- Treat SSR as an architecture decision, not a checkbox.
- Understand hydration before debugging hydration errors.
- Keep browser-only APIs behind appropriate lifecycle/platform boundaries.
- Avoid leaking user-specific server data through caches.
- Measure SEO, load performance, server cost, and hydration behavior together.
