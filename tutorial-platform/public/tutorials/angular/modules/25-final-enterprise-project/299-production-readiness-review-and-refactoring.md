# Day 299 — Production Readiness Review and Refactoring

Review the complete application as a production system and refactor where boundaries or behavior are weak.

## Goal
Find architectural debt before the final demo.

## Review Areas
- feature boundaries
- dependency direction
- state ownership
- shared contracts
- error handling
- accessibility
- security
- performance
- tests
- configuration
- deployment
- documentation

## Exercise
Create a production-readiness checklist. Refactor at least three concrete issues and explain why each change improves maintainability or reliability.

## Common Mistakes
Refactoring only for aesthetics; changing architecture without evidence; leaving known test or build failures for the demo.

## Interview Questions
1. How do you identify architectural debt?
2. When should you refactor versus accept technical debt?
3. What evidence would you require before calling an application production-ready?

## Outcome
The final system has undergone an explicit architecture and production-readiness review.
