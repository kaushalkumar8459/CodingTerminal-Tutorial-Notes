# Day 44 Interview Questions — Host Bindings and Host Listeners

## Interview Goal
Explain **Host Bindings and Host Listeners**, implement the relevant Angular pattern, discuss trade-offs, and apply it to a realistic JobHub scenario.

## Interview Questions

### 1. What is host binding?
**Expected Answer:** A way for a directive to bind a property, class, or style on its host element, either with `@HostBinding` or the `host` metadata object.

### 2. What is a host listener?
**Expected Answer:** A way for a directive to listen to events on its host element, either with `@HostListener` or the `host` metadata object.

### 3. What are the two ways to declare host bindings and listeners in Angular?
**Expected Answer:** The `@HostBinding`/`@HostListener` decorators, or the `host` metadata object in the directive's `@Directive` decorator.

### 4. Why is the host metadata approach often preferred for new code?
**Expected Answer:** It keeps the host contract declared in one place in the decorator, which can make the directive's behavior easier to scan and maintain.

### 5. Why should a directive prefer Angular host bindings over direct DOM manipulation?
**Expected Answer:** Host bindings integrate with Angular's change detection and rendering, avoiding manual DOM mutation that can drift out of sync with application state.

### 6. When would you use a host listener instead of a template event binding?
**Expected Answer:** When the behavior should be reusable across any host element the directive is applied to, rather than repeated in every template.

### 7. What is a common mistake when using host listeners?
**Expected Answer:** Listening to unnecessary global events or building complex application workflows inside a directive instead of keeping it focused on host behavior.

### 8. JobHub scenario: build a HoverCardDirective that adds a highlighted class on mouseenter and removes it on mouseleave. How would you implement this with host bindings/listeners?
**Expected Answer:** Use host listeners for `mouseenter` and `mouseleave` to update an internal flag, and a host binding on `class.highlighted` driven by that flag, avoiding manual DOM class manipulation.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?
