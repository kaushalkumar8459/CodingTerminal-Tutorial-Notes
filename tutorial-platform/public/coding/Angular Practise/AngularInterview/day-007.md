# Day 7 — First Mini Project: Interview Questions

## Topic

**Personal Profile App using Header, Profile, Skills and Footer**

## Interview Goal

Combine the fundamentals into a small component-based application.

---

## Interview Questions

### Q1. What should the Personal Profile App demonstrate?

**Expected Answer:**
It should demonstrate component creation, composition, templates, basic bindings and component styles.

### Q2. Why split the profile page into Header, Profile, Skills and Footer components?

**Expected Answer:**
Each component represents a focused UI responsibility and makes the page easier to understand and evolve.

### Q3. What is component composition?

**Expected Answer:**
It is building a larger UI by combining smaller components.

### Q4. Should services or routing be added to this project?

**Expected Answer:**
Not yet. They should be introduced only when the application has a real need for shared business logic or navigation.

### Q5. How would you explain the project in an interview?

**Expected Answer:**
Explain the requirement, component boundaries, data displayed, interactions used, and why each Angular concept was introduced.

### Q6. Scenario: The Profile component has become very large. What would you consider?

**Expected Answer:**
Identify cohesive UI sections that can become child components without creating unnecessary fragmentation.

### Q7. Practical: Add Header, Profile, Skills and Footer as standalone components and compose them into the application.

**Expected Answer:**
The learner should build and compile the application and explain each component boundary.

---

## Interviewer Follow-Ups

Be prepared to answer these without memorizing definitions:

- Why is this concept needed at this point in an Angular application?
- What problem does it solve?
- How would you use it in a real project?
- What common mistake can a beginner make with it?
- How would you debug a problem involving this concept?

## Scenario Practice

**JobHub scenario:** Apply today's concept to the JobHub application. Explain the problem first, then identify the Angular feature that solves it. Do not introduce later concepts unless the scenario genuinely requires them.

## Common Interview Trap

Do not answer only with a definition. Follow the pattern:

```text
Definition → Why → Example → Project usage → Trade-off / limitation
```

## Self-Assessment

1. Explain today's topic in your own words.
2. Give one real-world use case.
3. Explain why it was introduced at this stage of the roadmap.
4. Write a small example without copying the notes.
5. Explain one common mistake or limitation.

## Interview Readiness

You are ready to move forward when you can explain the concept clearly, implement the basic use case, and connect it to the JobHub project without relying on memorized wording.
