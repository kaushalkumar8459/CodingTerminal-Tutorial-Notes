# Day 114 — Authentication Headers and Request Context

## Interview Goal
Understand how authentication metadata and request-specific context can be carried through Angular HTTP requests.

## Level 1 — Basic Questions
1. Why do protected APIs require authentication information?
2. What is an authorization header?
3. What is request context?
4. Why should authentication logic not be duplicated in every API service?
5. What is the difference between authentication metadata and business data?

## Level 2 — Understanding
1. When should an auth interceptor add credentials?
2. Why might some requests need to opt out of authentication?
3. What information should not be placed in query parameters?
4. How can request context help an interceptor make a decision?
5. Why must the backend remain authoritative for authorization?

## Level 3 — Practical
1. Design an authenticated request flow.
2. Mark selected requests as public.
3. Use request context for interceptor behavior where appropriate.
4. Keep feature services independent of token construction.
5. Design an API contract for authenticated job operations.

## JobHub Scenarios
1. Job search is public but applying requires authentication. How should the HTTP layer distinguish them?
2. A recruiter endpoint requires a special permission. Should the frontend decide whether the user is authorized?
3. A request must skip a retry policy. How could request context represent that requirement?
4. Multiple APIs have different authentication requirements. How would you avoid hard-coded checks everywhere?

## Interviewer Follow-Ups
- What is HttpContext used for?
- Can a request context value itself authorize a user?
- Where should role and permission enforcement occur?
- How would you test context-driven interceptor behavior?

## Coding Question
Design a request option using Angular HTTP context to mark an endpoint as public.

## Debugging Scenario
A public endpoint receives an authentication header and fails through an upstream gateway. Identify where the policy should be adjusted.

## Common Interview Traps
- Treating request context as a security boundary.
- Putting authorization decisions only in the UI.
- Sending sensitive information through URLs.
- Hard-coding endpoint checks in many services.

## Project Connection — JobHub
Request context helps coordinate cross-cutting transport policies while backend authorization remains authoritative.

## Quick Revision
Frontend request metadata can influence transport behavior, but it must never replace server-side authorization.
