# Day 20 Interview Questions — @switch

## Interview Goal
Be able to explain **@switch**, write the relevant Angular code, discuss trade-offs, and apply it to a realistic JobHub feature.

## Interview Questions

### 1. What does @switch do?
**Expected Answer:** It selects a template branch based on the value of an expression.

### 2. When is @switch preferable to many @if branches?
**Expected Answer:** When one discriminating value maps to several mutually exclusive variants.

### 3. What defines a switch branch?
**Expected Answer:** Use @case inside the @switch block.

### 4. What is @default?
**Expected Answer:** It renders when no case matches.

### 5. Can @switch handle string status values?
**Expected Answer:** Yes, it can switch on string values and other supported expression values.

### 6. How should job statuses be modeled?
**Expected Answer:** Use a typed status value and map known statuses to intentional UI variants.

### 7. Why keep a default branch?
**Expected Answer:** It provides safe behavior for unexpected runtime values or future backend statuses.

### 8. Should domain rules live entirely in @switch?
**Expected Answer:** No. @switch should primarily select presentation; domain decisions belong in appropriate application logic.

### 9. JobHub scenario: backend introduces a new status unexpectedly. What should happen?
**Expected Answer:** Render a safe default state rather than crashing or showing an undefined visual state.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular approach could solve the same problem?
- What happens when the data changes?
- How would you test this behavior?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not memorize syntax alone. Explain **why** the pattern fits the UI state and which layer owns the underlying data.
