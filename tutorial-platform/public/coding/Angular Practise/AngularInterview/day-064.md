# Day 64 Interview Questions — InjectionToken and Configuration

## Interview Goal
Understand typed dependency-injection tokens and configuration boundaries.

## Interview Questions

### 1. What is InjectionToken?
**Expected Answer:** A typed DI token used for values or abstractions that are not naturally identified by a class.

### 2. Why use it for configuration?
**Expected Answer:** It creates an explicit typed DI boundary and keeps environment-specific values out of application logic.

### 3. Can an InjectionToken have a factory?
**Expected Answer:** Yes. A factory can create its value and use other injected dependencies.

### 4. What is a multi provider?
**Expected Answer:** A token configured for multiple providers can resolve a collection of provided values.

### 5. Common mistake?
**Expected Answer:** Reading environment-specific globals throughout the application instead of using a clear configuration boundary.

### 6. JobHub scenario
**Expected Answer:** Provide the API base URL through a typed configuration token at application bootstrap.

## Interviewer Follow-Ups
- Why not hard-code the URL?
- Where should runtime configuration be loaded?
- How would you test configuration consumers?
- When would a factory provider be useful?

## Common Interview Trap
Do not confuse a configuration value with a service. Both can be dependencies, but they can use different DI tokens and provider strategies.
