# Day 119 — Mini Project: Job Search API Dashboard

## Interview Goal
Build a realistic API-backed job search experience using typed HTTP architecture.

## Level 1 — Basic Questions
1. What API operations does the dashboard need?
2. Which state should the UI represent?
3. Which filters belong in query parameters?
4. What should happen when there are no jobs?
5. What should happen when the API fails?

## Level 2 — Understanding
1. How would you model pagination?
2. How would you prevent stale search responses?
3. Where should API-to-UI mapping occur?
4. Where should loading and error state live?
5. How would you test the dashboard without a real backend?

## Level 3 — Practical
1. Create a typed JobApiService.
2. Implement search with filters and pagination.
3. Add loading, empty, success, and error states.
4. Add retry behavior.
5. Map API models to UI models.
6. Keep the component independent from URL construction.

## JobHub Scenarios
1. Search filters change rapidly while requests are in flight. How should the UI handle them?
2. The backend returns a page with no jobs but indicates more pages are unavailable. What state should render?
3. A refresh fails while old jobs are visible. How should the screen behave?
4. The API contract changes from `items` to `results`. Which layer should change?

## Interviewer Follow-Ups
- Why use an API service?
- Why use typed models?
- Where would you add an interceptor?
- How would you test loading, empty, success, and error states?

## Coding Question
Implement the core architecture for the Job Search API Dashboard using strict TypeScript and modern Angular control flow.

## Debugging Scenario
The dashboard makes duplicate requests and occasionally displays stale results. Identify possible causes in request triggering and async coordination.

## Common Interview Traps
- Calling APIs directly from templates.
- Using untyped response data.
- Treating empty as error.
- Ignoring stale-request handling.

## Project Connection — JobHub
This mini project closes the first HTTP block and prepares the learner for advanced HTTP, authentication, and state management.

## Quick Revision
A production API dashboard combines typed contracts, data-access boundaries, explicit async state, and resilient request handling.

## Interview Readiness
You are ready when you can design the data flow before implementing the screen.
