# Day 109 — Request Parameters, Headers and Options

## Interview Goal
Understand how to control Angular HTTP requests without leaking transport details into UI components.

## Level 1 — Basic Questions
1. What are query parameters?
2. What are HTTP headers?
3. What is a request body?
4. What is the purpose of request options in HttpClient?
5. Why should headers and parameters be built deliberately?

## Level 2 — Understanding
1. Compare query parameters, headers, and request body.
2. When would you use `HttpParams)?
3. When would you send `HttpHeaders)?
4. Why might a request need credentials or a specific response type?
5. What should be centralized in an interceptor instead of repeated in every service?

## Level 3 — Practical
1. Build typed query parameters for job filtering.
2. Add an `Accept` header where the API contract requires it.
3. Add correlation/request metadata through an appropriate interceptor strategy.
4. Use request options for non-default response handling when required.
5. Keep feature services independent of low-level authentication header construction.

## Level 4 — JobHub Scenarios
1. Every authenticated API request needs the same access token. Where should that concern live?
2. Job search supports optional filters. How do you avoid meaningless empty parameters?
3. A file download requires a binary response. How does that differ from a normal JSON request?
4. A backend requires a tenant or organization identifier. Would you put it in the URL, header, or body? Explain based on the API contract.

## Level 5 — Interviewer Follow-Ups
- What are the risks of manually duplicating authorization headers?
- What belongs in an interceptor versus a feature API service?
- How do you test request headers and query parameters?
- Can request headers be trusted for authorization?

## Coding Question
Implement a typed search request with optional filters and query parameters, keeping transport construction inside the API service.

## Debugging Scenario
A request sends `?location=` and `?experience=` when filters are empty. Explain how you would construct parameters cleanly.

## Common Interview Traps
- Putting authorization logic in every component.
- Confusing headers with secure authorization decisions.
- Manually concatenating URLs.
- Sending UI-only values as API parameters.

## Project Connection — JobHub
Clean request construction becomes important as JobHub adds filtering, authentication, multi-tenant data, uploads, and downloads.

## Quick Revision
Parameters describe query selection, headers describe request metadata, and bodies carry operation data according to the API contract.

## Interview Readiness
You are ready when you can design request options without coupling UI code to HTTP transport details.
