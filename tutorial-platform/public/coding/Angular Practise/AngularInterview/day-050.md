# Day 50 Interview Questions — Why Component Composition?

## Interview Goal
Explain **Why Component Composition?**, implement the relevant Angular pattern, discuss trade-offs, and apply it to a realistic JobHub scenario.

## Interview Questions

### 1. What is component composition?
**Expected Answer:** It builds a larger UI by combining focused components rather than putting all UI behavior into one component.

### 2. Why is composition important in Angular?
**Expected Answer:** It improves reuse, separation of responsibilities, testability, and maintainability.

### 3. What is the difference between composition and inheritance for UI?
**Expected Answer:** Composition combines components through contracts and structure; inheritance creates tighter class relationships and is usually not the primary UI reuse mechanism.

### 4. What makes a component composable?
**Expected Answer:** A clear API, focused responsibility, predictable inputs/outputs, and flexible content or child composition.

### 5. How does content projection support composition?
**Expected Answer:** A reusable component can provide structure while consumers supply content through ng-content.

### 6. When should a component be split into smaller components?
**Expected Answer:** When a section has a distinct responsibility, repeated UI pattern, independent state, or a useful reusable contract.

### 7. What is over-componentization?
**Expected Answer:** Splitting UI into many tiny components without meaningful boundaries, which can increase complexity and communication overhead.

### 8. How should a reusable component avoid domain coupling?
**Expected Answer:** Expose generic typed UI contracts and keep feature-specific orchestration outside the reusable component.

### 9. JobHub scenario: a dashboard contains header, filters, job list, job card, and actions. How would you compose it?
**Expected Answer:** Use focused components with explicit contracts, letting the feature/container coordinate data and actions while reusable UI components stay domain-light.

## Interviewer Follow-Ups
- Why did you choose this component boundary?
- What alternative design could solve the same problem?
- Who owns the state?
- How would you test the composition?
- What would you change for a large enterprise application?

## Common Interview Trap
Do not split components merely to make files smaller. A component should have a meaningful responsibility and a clear contract.
