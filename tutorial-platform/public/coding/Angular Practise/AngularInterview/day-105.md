# Day 105 — Why HTTP & API Integration?

## Interview Goal
Understand why frontend applications need APIs and how Angular should interact with backend systems.

## Level 1 — Basic Questions
1. What is HTTP?
2. What is an API?
3. Why does an Angular application need a backend API?
4. What is the difference between a client and a server?
5. What are GET, POST, PUT, PATCH, and DELETE commonly used for?

## Level 2 — Understanding
1. Explain request, response, headers, body, and status code.
2. Why should API calls not be scattered throughout UI components?
3. What is the difference between transport models and UI models?
4. Why should HTTP errors be handled explicitly?
5. What does idempotency mean at a high level?

## Level 3 — Practical
1. Design API endpoints for JobHub jobs and applications.
2. Define TypeScript interfaces for request and response payloads.
3. Decide which operations should use GET, POST, PATCH, and DELETE.
4. Design loading, success, empty, and error states for an API-backed page.
5. Explain frontend behavior when the network is unavailable.

## Level 4 — JobHub Scenarios
1. Job search needs filters, pagination, and sorting. What should the API contract contain?
2. A recruiter edits a job while two browser tabs contain the same record. What consistency concerns exist?
3. The jobs API returns fields the UI does not need. Should the component consume the raw response directly?
4. The API changes a field name. How can the frontend limit the impact?

## Level 5 — Interviewer Follow-Ups
- Why use a data-access service?
- What belongs in an API contract?
- How do HTTP status codes influence UI behavior?
- Where should request/response mapping happen?

## Coding Question
Design a typed Job API contract for list, details, create, update, and delete operations.

## Debugging Scenario
Five components each call the same jobs endpoint independently. Explain the architectural and performance problems this can create.

## Common Interview Traps
- Treating HTTP as only GET requests.
- Mixing API DTOs directly into every template.
- Ignoring cancellation and stale requests.
- Assuming network success means business success.

## Project Connection — JobHub
HTTP integration turns JobHub from a local UI into a real application backed by services.

## Quick Revision
A strong Angular API layer has clear contracts, typed models, centralized data access, explicit UI states, and error handling.

## Interview Readiness
You are ready when you can design an API integration boundary before writing the component.
