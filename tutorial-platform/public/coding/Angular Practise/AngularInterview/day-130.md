# Day 130 — Project Planning and Requirements

## Interview Goal
Begin the complete JobHub Angular project by translating requirements into features, boundaries, and deliverables.

## Level 1 — Basic Questions
1. Why should a project be planned before implementation?
2. What is a functional requirement?
3. What is a non-functional requirement?
4. Why are user roles important in application planning?
5. What is a feature boundary?

## Level 2 — Understanding
1. Convert a job platform idea into candidate, recruiter, and admin capabilities.
2. Separate user stories from technical implementation details.
3. Identify dependencies between features.
4. Identify performance, accessibility, security, and responsive requirements.
5. Why should API assumptions be documented early?

## Level 3 — Practical
1. Write JobHub functional requirements.
2. Define primary user journeys.
3. Create an initial feature map.
4. Identify required API capabilities.
5. Define acceptance criteria for major features.

## JobHub Scenarios
1. Candidate can search, save, and apply; recruiter can create and manage jobs; admin manages users and permissions. How would you partition these capabilities?
2. Which requirements are essential for the first project increment?
3. Which features can be implemented independently?
4. Which requirements create cross-feature dependencies?

## Interviewer Follow-Ups
- How do requirements affect Angular architecture?
- How do you prevent scope from expanding uncontrollably?
- What makes a good acceptance criterion?
- How would you communicate technical constraints to stakeholders?

## Coding Question
Create a feature map for JobHub showing candidate, recruiter, admin, shared, and platform capabilities.

## Debugging Scenario
Developers start building components before agreeing on roles and workflows, causing repeated rewrites. What planning step was missing?

## Common Interview Traps
- Starting from UI screens instead of user journeys.
- Mixing implementation details with requirements.
- Ignoring non-functional requirements.
- Treating backend contracts as an afterthought.

## Project Connection — JobHub
Day 130 turns the previous Angular concepts into a structured capstone plan.

## Quick Revision
Good project planning defines users, workflows, requirements, boundaries, dependencies, and acceptance criteria before implementation.

## Interview Readiness
You are ready when you can turn an application idea into implementable, testable requirements.
