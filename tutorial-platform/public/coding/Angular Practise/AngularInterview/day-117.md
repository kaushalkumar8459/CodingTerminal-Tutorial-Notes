# Day 117 — API Configuration

## Interview Goal
Design environment-aware API configuration without scattering URLs and secrets through Angular code.

## Level 1 — Basic Questions
1. Why should API URLs be configurable?
2. What is environment-specific configuration?
3. Why should secrets not be stored in frontend source code?
4. What is runtime configuration?
5. Where should a feature obtain its API base URL?

## Level 2 — Understanding
1. Compare build-time and runtime configuration.
2. Why is a frontend environment file not a secret store?
3. How can dependency injection provide configuration?
4. Why is hard-coded URL construction difficult to maintain?
5. What should happen when required configuration is missing?

## Level 3 — Practical
1. Define a typed API configuration object.
2. Provide it through Angular dependency injection.
3. Support development and production API endpoints.
4. Validate required configuration at startup.
5. Keep API services independent of deployment-specific values.

## JobHub Scenarios
1. JobHub runs locally, in test, staging, and production. How should the API base URL change?
2. A deployment platform injects runtime configuration. How can Angular consume it?
3. A developer puts a private API key in environment.ts. What is wrong?
4. A remote micro frontend needs a backend URL. How should configuration be coordinated?

## Interviewer Follow-Ups
- What is an InjectionToken useful for?
- Why is runtime configuration valuable for containerized deployments?
- Can a frontend hide a secret?
- How would you test missing configuration?

## Coding Question
Create a typed `API_BASE_URL` InjectionToken and inject it into a JobApiService.

## Debugging Scenario
Production calls localhost because a URL was hard-coded in a service. Explain the configuration boundary that was missed.

## Common Interview Traps
- Calling frontend configuration secrets.
- Hard-coding production URLs.
- Mixing configuration with business logic.
- Assuming build-time configuration covers every deployment model.

## Project Connection — JobHub
Configuration strategy prepares JobHub for CI/CD, runtime deployment, and later micro frontend environments.

## Quick Revision
Configuration belongs at application boundaries; secrets must remain server-side.
