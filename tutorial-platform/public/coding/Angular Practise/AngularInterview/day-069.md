# Day 69 Interview Questions — Why Component Lifecycle Matters

## Interview Goal
Understand Angular component lifecycle stages and place setup, rendering work, reactions, and cleanup appropriately.

## Interview Questions

### 1. What is the Angular component lifecycle?
**Expected Answer:** It is the sequence of component creation, input processing, rendering/checking, and destruction.

### 2. Why learn lifecycle hooks?
**Expected Answer:** They help place initialization, input reactions, DOM-dependent work, and cleanup in appropriate locations.

### 3. Why is cleanup important?
**Expected Answer:** Timers, listeners, subscriptions, and other resources can otherwise outlive the component.

### 4. Should heavy work run on repeated checks?
**Expected Answer:** No. Expensive repeated work can create unnecessary rendering cost.

### 5. How do signals affect lifecycle design?
**Expected Answer:** Reactive dependencies can reduce manual synchronization while lifecycle APIs remain useful for setup, DOM access, and cleanup.

### 6. What is a common lifecycle anti-pattern?
**Expected Answer:** Putting unrelated business logic into hooks simply because those hooks execute during the lifecycle.

### 7. JobHub scenario
**Expected Answer:** If JobDetails starts polling, the polling resource must be stopped when the component is destroyed.

## Interviewer Follow-Ups
- Which work belongs in initialization?
- Which work requires a rendered view?
- How do you clean up resources?
- How can repeated checks affect performance?

## Common Interview Trap
Do not choose lifecycle hooks by memorized sequence alone. Choose them based on what must exist before the work can safely run.
