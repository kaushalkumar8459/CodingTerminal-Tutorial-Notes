# Day 100 Interview Questions — Cross-Field Validation

## Interview Goal
Explain **Cross-Field Validation**, implement the relevant Angular pattern, and apply it to a realistic JobHub scenario.

## Interview Questions

### 1. What is cross-field validation?
**Expected Answer:** Validation where the result depends on values from two or more controls.

### 2. Why does it usually belong on a FormGroup?
**Expected Answer:** The group has access to the related controls needed to evaluate the rule.

### 3. Give an example of cross-field validation.
**Expected Answer:** Confirm password matching, start/end dates, minimum/maximum salary ranges, or conditional requirements.

### 4. What should a cross-field validator return?
**Expected Answer:** A predictable validation error object when invalid, otherwise null.

### 5. How should error messages be displayed?
**Expected Answer:** Associate the message with the relevant group or field UX rather than exposing implementation details.

### 6. What is a common mistake?
**Expected Answer:** Duplicating the same rule in multiple controls and creating inconsistent error states.

### 7. Should cross-field validation replace backend validation?
**Expected Answer:** No. Backend validation remains authoritative for submitted business rules.

### 8. How would you test it?
**Expected Answer:** Test valid combinations, invalid combinations, boundary values, and changes to each participating control.

### 9. JobHub scenario: maximum salary must be greater than or equal to minimum salary. What design fits?
**Expected Answer:** A FormGroup-level validator can compare both salary controls and expose a range validation error.

## Interviewer Follow-Ups
- Why did you choose this approach?
- What alternative Angular API could solve the problem?
- What is the ownership or validation boundary?
- How would you test it?
- What changes at enterprise scale?

## Common Interview Trap
Do not memorize syntax alone. Explain **why**, **when**, and **where** the Angular feature should be used.
