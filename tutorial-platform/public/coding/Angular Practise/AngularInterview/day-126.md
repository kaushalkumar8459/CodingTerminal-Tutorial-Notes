# Day 126 — Authentication Storage and Security

## Interview Goal
Understand the security trade-offs involved in browser-side authentication state and credential storage.

## Level 1 — Basic Questions
1. Where can browser applications store client-side state?
2. What is localStorage?
3. What is sessionStorage?
4. What are cookies?
5. Why is sensitive credential storage a security concern?

## Level 2 — Understanding
1. Compare common browser storage mechanisms from a security perspective.
2. Why does XSS affect browser-stored tokens?
3. What security properties can HttpOnly cookies provide?
4. Why does cookie-based authentication introduce CSRF considerations?
5. Why should the frontend never treat storage contents as trusted identity?

## Level 3 — Practical
1. Document a session-storage strategy for JobHub.
2. Minimize sensitive data stored in browser-accessible storage.
3. Design logout cleanup.
4. Define secure cookie expectations for a backend team.
5. Document assumptions instead of claiming one storage method is universally safest.

## JobHub Scenarios
1. A team wants to store a long-lived access token in localStorage. What risks should be reviewed?
2. The backend uses HttpOnly cookies. What frontend behavior changes?
3. A user shares a computer. What session behavior should the application consider?
4. Sensitive profile information remains in browser cache after logout. How should it be cleared or avoided?

## Interviewer Follow-Ups
- HttpOnly versus localStorage?
- Secure and SameSite cookie attributes?
- Why does CSRF matter with cookies?
- Can frontend storage ever be treated as a secret store?

## Coding Question
Design a documented authentication storage strategy for JobHub, including logout and threat assumptions.

## Debugging Scenario
A token is readable from JavaScript even though the team expected it to be protected from script access. Identify the storage/configuration issue.

## Common Interview Traps
- Calling localStorage a secure token vault.
- Ignoring XSS.
- Ignoring CSRF for cookie sessions.
- Storing more sensitive information than the UI needs.

## Project Connection — JobHub
Storage decisions affect the security architecture of every authenticated feature.

## Quick Revision
Browser storage is a security boundary with trade-offs; never treat client-side data as inherently trusted.

## Interview Readiness
You are ready when you can compare storage choices using explicit threat assumptions rather than slogans.
