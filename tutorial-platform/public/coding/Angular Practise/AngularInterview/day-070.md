# Day 70 Interview Questions — Component Creation and Initialization

## Interview Goal
Understand component creation, dependency resolution, input initialization, ngOnInit, and post-render work.

## Interview Questions

### 1. What happens when Angular creates a component?
**Expected Answer:** Angular creates the instance, resolves dependencies, initializes inputs, creates the view, and runs the relevant lifecycle and rendering steps.

### 2. What should a constructor normally do?
**Expected Answer:** Keep it focused on class instantiation and dependency setup rather than complex application initialization.

### 3. What is ngOnInit for?
**Expected Answer:** It is a lifecycle hook for initialization logic that depends on Angular having initialized the component's inputs.

### 4. Constructor vs ngOnInit?
**Expected Answer:** The constructor runs during class instantiation; ngOnInit runs after Angular initializes the component's inputs.

### 5. When is afterNextRender useful?
**Expected Answer:** For browser-side work that should happen after Angular has rendered, especially work involving the rendered DOM.

### 6. What is a common initialization mistake?
**Expected Answer:** Assuming input values or DOM state are available at constructor time when they are not.

### 7. How should input-driven loading be handled?
**Expected Answer:** Use an appropriate input/reactive pattern so loading reacts correctly to supplied or changed input values.

### 8. JobHub scenario
**Expected Answer:** JobDetails should load based on its supplied jobId using an input-aware reactive or lifecycle pattern rather than assuming constructor timing.

## Interviewer Follow-Ups
- When would you use ngOnChanges instead?
- When does DOM access become safe?
- How do signals change input-driven initialization?
- How would you test initialization behavior?

## Common Interview Trap
Do not put all initialization into the constructor. Distinguish dependency setup, input-dependent work, and post-render browser work.
