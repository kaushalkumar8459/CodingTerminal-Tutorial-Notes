# Day 67 Interview Questions — Feature Service Architecture

## Interview Goal
Understand feature-oriented service boundaries and dependency direction.

## Interview Questions

### 1. What is feature-oriented service architecture?
**Expected Answer:** Services are organized around feature responsibilities instead of one global collection of unrelated utilities.

### 2. Why separate data access from feature state?
**Expected Answer:** It prevents HTTP details from becoming tightly coupled to UI state and orchestration.

### 3. Where should API models be transformed?
**Expected Answer:** At a deliberate data boundary where backend contracts are converted into domain or UI models when needed.

### 4. Why use explicit service boundaries?
**Expected Answer:** They make ownership, testing, dependencies, and replacement easier to reason about.

### 5. What is a common anti-pattern?
**Expected Answer:** A service directly manipulating unrelated features' internal state.

### 6. How should cross-feature communication work?
**Expected Answer:** Prefer explicit contracts or appropriately owned shared state instead of hidden service coupling.

### 7. JobHub scenario
**Expected Answer:** Share job data-access logic where appropriate while keeping candidate and recruiter workflow orchestration inside their own feature boundaries.

## Interviewer Follow-Ups
- How would you define dependency direction?
- Where should model mapping happen?
- How do feature boundaries help testing?
- When is shared state justified?

## Common Interview Trap
Shared domain data does not mean all feature workflow logic belongs in one shared service.
