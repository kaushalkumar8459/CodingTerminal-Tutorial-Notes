# Day 102 — Form UX

## Interview Goal
Design forms that are understandable, accessible, responsive, and predictable.

## Level 1 — Basic Questions
1. What makes a form user-friendly?
2. When should validation messages appear?
3. What is the difference between invalid, touched, dirty, and submitted states?
4. Why should important controls have accessible labels?
5. Why should submit buttons reflect submission state?

## Level 2 — Understanding
1. Compare immediate validation with validation after blur or submit.
2. How should server-side validation errors be displayed?
3. Why should loading state prevent duplicate submissions?
4. How should a form communicate success and failure?
5. What is the role of `aria-describedby` for validation messages?

## Level 3 — Practical
1. Build a registration form with accessible validation messages.
2. Disable submission while an API request is running.
3. Preserve user-entered values after a failed request.
4. Focus the first invalid field in a long form.
5. Implement an unsaved-changes experience.

## Level 4 — JobHub Scenarios
1. A recruiter creates a job with 15 fields. How would you structure validation UX?
2. Candidate application fails because the email already exists. Where should the error appear?
3. Users repeatedly click Apply and create duplicate submissions. How would you prevent it?
4. A mobile user cannot understand which field is invalid. What improvements would you make?

## Level 5 — Interviewer Follow-Ups
- How do touched and dirty differ?
- Should client validation replace backend validation?
- How would you handle field-level and form-level server errors?
- How would you test accessible validation behavior?

## Coding Question
Implement a typed job application form with field errors, submit loading state, and an accessible error summary.

## Debugging Scenario
The submit button remains enabled while a request is running, allowing duplicate submissions. Explain the state model you would introduce.

## Common Interview Traps
- Relying only on red borders.
- Hiding validation messages from assistive technologies.
- Treating client validation as security.
- Losing form values after failed submission.

## Project Connection — JobHub
Good form UX is critical for job creation, applications, profile editing, and recruiter workflows.

## Quick Revision
Production forms combine validation state, submission state, accessibility, feedback, and recovery behavior.

## Interview Readiness
You are ready when you can explain not just how validation works, but how users experience validation.
