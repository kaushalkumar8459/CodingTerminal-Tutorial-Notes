# Day 195 — SignalStore with Services and DI

## Interview Goal
Explain and apply this state-management concept in modern Angular using strict TypeScript, Signals, RxJS where appropriate, and clear feature boundaries.

## Level 1 — Basic Questions
1. What problem does this topic solve?
2. What is the simplest example?
3. Why is it useful in Angular?
4. What common beginner mistake should be avoided?

## Level 2 — Understanding
1. Explain the state/data flow step by step.
2. Compare this approach with its closest alternative.
3. How do ownership, immutability, derived state, and lifecycle affect the design?
4. When should you avoid this approach?

## Level 3 — Practical
1. How would you apply it to JobHub?
2. Which state should remain local and which should be shared?
3. How would you test the state transitions?
4. How would you handle loading, errors, concurrency, and cleanup?

## JobHub Scenarios
Injecting services into SignalStore features, API orchestration, dependency boundaries, and testability. JobHub scenarios: loading jobs through an API service. Coding: connect a typed store to a service. Debugging: diagnose provider or dependency issues.

## Interviewer Follow-Ups
- Why does this state belong at this scope?
- Why use Signals or SignalStore instead of another approach?
- How would multiple features consume the same information safely?
- How would you prevent stale, duplicated, or conflicting state?
- What would you change if the application grew significantly?

## Coding Question
Implement a small JobHub state-management example based on this day's concept using strict TypeScript and modern Angular APIs. Avoid `any` and unnecessary global state.

## Debugging Scenario
A JobHub feature has stale data, duplicated state, unexpected updates, excessive recomputation, incorrect loading/error state, or dependency-boundary problems. Explain how you would reproduce, inspect, diagnose, and fix the issue.

## Common Interview Traps
- Making every value global state.
- Storing values that should be derived.
- Mutating collections in place.
- Putting all business logic into components.
- Creating oversized stores or facades.
- Ignoring async race conditions and lifecycle cleanup.

## Project Connection — JobHub
Apply today's concept to JobHub search, saved jobs, authentication context, recruiter workflows, applications, or admin dashboards.

## Quick Revision
Review state ownership, data flow, immutable updates, derived state, async state, store boundaries, performance, and testing.

## Interview Readiness
You are ready when you can design the state boundary before writing the store and clearly justify the trade-offs.
