# Day 107 — GET Requests and Typed Responses

## Interview Goal
Build safe, typed GET requests and understand how response contracts affect Angular UI code.

## Level 1 — Basic Questions
1. How do you make a GET request with `HttpClient)?
2. How do you provide a TypeScript response type?
3. What is the difference between a response type annotation and runtime validation?
4. What is the purpose of query parameters?
5. Why should pagination be part of the API contract?

## Level 2 — Understanding
1. Explain `HttpClient.get<T>()`.
2. Does TypeScript verify that the server actually returned type `T)?
3. When would you use `HttpParams)?
4. How should an API represent paginated results?
5. Why should UI code avoid assuming every response is a non-empty array?

## Level 3 — Practical
1. Create a typed `JobListResponse`.
2. Add search, location, page, and pageSize query parameters.
3. Map API jobs into a UI-friendly model.
4. Handle an empty result correctly.
5. Add cancellation or stale-request protection for rapidly changing search terms.

## Level 4 — JobHub Scenarios
1. Searching for "Angular" produces multiple pages. How would you model pagination?
2. The API returns `null` for an optional field. How should strict TypeScript model it?
3. The server adds an unexpected property. Should the UI fail?
4. Search requests return out of order. How can the UI avoid stale results?

## Level 5 — Interviewer Follow-Ups
- Does a generic type validate JSON at runtime?
- Where would runtime schema validation happen if required?
- When would you use `switchMap` for search?
- How do you distinguish empty results from API failure?

## Coding Question
Implement a typed `searchJobs(params)` method using `HttpParams` and a typed response model.

## Debugging Scenario
The UI expects `response.items`, but the backend returns `response.data`. Explain how a mapping boundary prevents this mismatch from spreading.

## Common Interview Traps
- Assuming TypeScript generics validate server JSON.
- Treating empty data as an error.
- Building query strings manually.
- Ignoring stale search responses.

## Project Connection — JobHub
Typed GET APIs power job search, filtering, recruiter lists, and admin screens.

## Quick Revision
Typed HTTP improves compile-time safety, but runtime API data still needs trustworthy contracts or validation.

## Interview Readiness
You are ready when you can explain both TypeScript typing and its limits.
