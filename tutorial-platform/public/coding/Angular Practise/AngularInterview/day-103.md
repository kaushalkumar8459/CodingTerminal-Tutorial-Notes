# Day 103 — Form Architecture and Reusable Patterns

## Interview Goal
Design maintainable Angular forms instead of placing all form logic inside one component.

## Level 1 — Basic Questions
1. What is form architecture?
2. Why should complex forms be broken into smaller sections?
3. When should form creation logic be extracted into a service or factory?
4. What is a reusable form component?
5. Why should validation rules have a clear ownership boundary?

## Level 2 — Understanding
1. Compare one large form component with section-based form components.
2. Where should API mapping logic live?
3. How would you separate UI form models from backend DTOs?
4. When should a child component own a `FormGroup)?
5. How can typed forms reduce integration bugs?

## Level 3 — Practical
1. Create a reusable JobDetails form section.
2. Create separate form models for candidate profile and API payload.
3. Extract repeated validators into reusable functions.
4. Build a form factory for create and edit modes.
5. Design draft saving without coupling UI code to HTTP.

## Level 4 — JobHub Scenarios
1. Job creation and editing share 80% of their fields. How would you avoid duplication?
2. Candidate and Recruiter Profile APIs differ but share UI controls. How would you model them?
3. A form component contains validation, API calls, navigation, notifications, and mapping. How would you refactor it?
4. Multiple screens use the same address fields. Would you duplicate the form or create a reusable component?

## Level 5 — Interviewer Follow-Ups
- What belongs in a form service versus a component?
- How do you prevent reusable components from becoming overly configurable?
- When is a nested `FormGroup) better than a CVA component?
- How would you test a reusable form section?

## Coding Question
Design a typed `JobFormFactory` that creates a create/edit Job form without duplicating control definitions.

## Debugging Scenario
An edit screen patches API data directly into the form and later submits UI-only fields back to the API. Identify the architectural problem.

## Common Interview Traps
- Coupling forms directly to backend DTOs.
- Duplicating validation logic.
- Creating giant reusable components.
- Mixing navigation, API, and UI responsibilities.

## Project Connection — JobHub
JobHub should use reusable form sections while keeping feature-specific orchestration inside candidate, recruiter, and admin features.

## Quick Revision
Good form architecture separates form models, reusable controls, validation, API mapping, and feature orchestration.

## Interview Readiness
You are ready when you can explain where each responsibility belongs in a complex Angular form.
