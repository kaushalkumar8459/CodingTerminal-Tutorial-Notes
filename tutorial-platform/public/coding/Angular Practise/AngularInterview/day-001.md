# Day 1 — Angular Interview Questions

## Topic

**What is Angular and Why Angular?**

## Interview Goal

By the end of this interview practice, the learner should be able to explain Angular in simple language, describe why a framework is useful, and distinguish Angular from plain JavaScript and other frontend approaches.

---

## Level 1 — Basic Questions

### Q1. What is Angular?

**Expected Answer:**

Angular is a TypeScript-based web application framework developed by Google for building scalable client-side applications. It provides built-in solutions for common application needs such as components, templates, routing, forms, dependency injection, HTTP communication, and testing.

### Q2. Is Angular a library or a framework?

**Expected Answer:**

Angular is a framework. It provides an opinionated application structure and an integrated set of tools and APIs for building complete web applications.

### Q3. Why do we need Angular when we already have JavaScript?

**Expected Answer:**

JavaScript provides the programming language and browser APIs, but a large application also needs consistent ways to organize UI, navigation, forms, data access, dependency management, testing, and application state. Angular provides conventions and built-in capabilities for these application-level problems.

### Q4. What can we build with Angular?

**Expected Answer:**

Angular can be used to build single-page applications, dashboards, enterprise applications, admin portals, e-commerce applications, learning platforms, and other complex browser-based applications.

### Q5. What is a Single Page Application (SPA)?

**Expected Answer:**

A SPA is a web application where the browser initially loads an application and then updates the displayed UI as the user navigates or interacts with it, instead of performing a full browser page reload for every application route.

### Q6. What is the role of Angular in an SPA?

**Expected Answer:**

Angular manages the application UI and its behavior in the browser. It provides components, templates, routing, services, forms, HTTP integration, and other application capabilities needed to build the SPA.

## Level 2 — Understanding

### Q7. What problems does Angular solve?

**Expected Answer:**

Angular helps solve common large-application problems such as:

- Organizing UI into components
- Managing templates and user interaction
- Navigating between application views
- Sharing business logic through services
- Managing dependencies through dependency injection
- Handling forms and validation
- Communicating with backend APIs
- Testing application behavior
- Maintaining consistent project structure

### Q8. What is a component in Angular?

**Expected Answer:**

A component is a primary building block of an Angular application's UI. It combines a template, application logic, and styling to represent a part of the user interface.

### Q9. What is the relationship between Angular and TypeScript?

**Expected Answer:**

Angular is built with TypeScript and provides first-class TypeScript support. TypeScript adds static typing and other language features that help developers build and maintain large applications.

### Q10. Does Angular replace HTML, CSS, and JavaScript?

**Expected Answer:**

No. Angular works with HTML, CSS, and JavaScript/TypeScript. It provides a framework and additional APIs for structuring and managing an application.

### Q11. What is Angular CLI?

**Expected Answer:**

Angular CLI is the command-line tool used to create, develop, test, build, and maintain Angular applications. For example, it can create a new application and generate Angular artifacts.

### Q12. Who develops Angular?

**Expected Answer:**

Angular is developed and maintained by Google together with its open-source community.

## Level 3 — Comparison Questions

### Q13. Angular vs plain JavaScript — what is the difference?

**Expected Answer:**

Plain JavaScript gives developers direct control over browser behavior and application code, but the developer must decide how to structure a large application. Angular provides an application framework with conventions and built-in capabilities for common concerns.

### Q14. Angular vs React — what is the difference?

**Expected Answer:**

Angular is a full frontend framework with an integrated set of application capabilities. React is primarily a UI library, and applications commonly add additional libraries or frameworks for concerns such as routing and state management. Both can be used to build large web applications.

### Q15. Why might a team choose Angular for an enterprise application?

**Expected Answer:**

A team may choose Angular when it values an integrated framework, consistent application patterns, TypeScript support, dependency injection, built-in routing/forms/HTTP capabilities, and long-term maintainability across a large team.

---

## Level 4 — Scenario Questions

### Q16. You are asked to build a large job portal. Why might you choose Angular?

**Expected Answer:**

I would evaluate the project requirements first. If the application needs a structured architecture, many reusable components, routing, forms, API integration, authentication, testing, and a large development team, Angular's integrated framework and conventions can provide a consistent foundation.

### Q17. Your team has many developers working on the same frontend. What Angular features can help?

**Expected Answer:**

Angular's component architecture, dependency injection, routing, TypeScript support, CLI tooling, conventions, testing tools, and modular feature boundaries can help teams maintain consistency and separation of responsibilities.

### Q18. A beginner says, "Angular is only for creating HTML pages." How would you explain it?

**Expected Answer:**

Angular does much more than render HTML. It provides a complete application framework for managing UI, user interaction, navigation, services, dependencies, forms, API communication, application state, testing, and other concerns.

## Debugging Scenario

### Q20. A developer says, "I can build the entire application with HTML, CSS and JavaScript, so Angular is unnecessary." How would you respond in an interview?

**Expected Answer:**

That is technically possible. The decision depends on application complexity and team requirements. For a small page, plain JavaScript may be sufficient. As an application grows, a framework can provide conventions and integrated solutions for component architecture, routing, forms, dependency injection, API communication, testing, and maintainability.

## Common Interview Traps

### Trap 1 — Saying Angular is a programming language

Angular is a **framework**, not a programming language.

### Trap 2 — Saying Angular replaces JavaScript

Angular uses TypeScript/JavaScript; it does not replace the underlying language.

### Trap 3 — Saying Angular automatically makes an application faster

Performance depends on application architecture, rendering strategy, network behavior, assets, code, and runtime usage. A framework does not automatically guarantee performance.

### Trap 4 — Saying Angular and React are exactly the same

Both are used for frontend development, but their scope and architectural approach differ.

### Trap 5 — Memorizing definitions

Interviewers often follow a definition with:

> "Give me an example from your project."

Always connect the answer to a real application.

## Quick Revision

Remember these five points:

1. Angular is a **web application framework**.
2. Angular uses **TypeScript** and works with HTML/CSS.
3. Angular uses **components** as core UI building blocks.
4. Angular provides integrated solutions for common application concerns.
5. The right framework choice depends on the application's requirements and team context.
