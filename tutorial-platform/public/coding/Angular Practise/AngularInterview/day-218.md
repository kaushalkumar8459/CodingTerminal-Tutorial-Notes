## Interviewer Follow-Ups
- What exactly are you testing or guaranteeing?
- How would you avoid testing implementation details?
- How would you keep tests stable as the UI evolves?
- How would you test accessibility, async behavior, errors, and cleanup where relevant?

## Coding Question
Implement a focused JobHub example based on this day's concept using standalone Angular and strict TypeScript. Prefer behavior-focused tests and avoid `any`.

## Debugging Scenario
A JobHub feature or test has incorrect behavior, flaky assertions, provider errors, accessibility regressions, timing issues, or unexpected dependencies. Explain how you would reproduce, inspect, diagnose, and fix it.

## Common Interview Traps
- Testing private implementation details instead of behavior.
- Using broad selectors that make tests fragile.
- Mocking everything without understanding the integration boundary.
- Ignoring accessibility and keyboard behavior.
- Making async tests depend on arbitrary timing.
- Allowing tests to use `any` to bypass type errors.
